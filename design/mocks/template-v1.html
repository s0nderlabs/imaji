One release in, a whole launch kit out

A developer who ships is a creator whose content is code.

imaji turns each release into the posts, the card and the film they never had time to make. Your own Mind writes them, remembering every release before this one. imaji only renders.

01

Hand your Mind the job

Paste this once into a chat with your own Mind. It is the whole job: what a kit is, the JSON to answer with, how to call the renderer, and when to skip a release and say why.

job/JOB.md
{{JOB}}
02

Drop the workflow in your repo

Save it as .github/workflows/imaji.yml. Two jobs: onboard, which lets your Mind read the repo once and propose your brand, and release, which runs every time you tag one.

templates/imaji.yml
{{WORKFLOW}}
MINDS_API_KEY
your Builder API key, from build.hellominds.ai
MIND_ID
your Mind’s id, lowercase
IMAJI_KIT_TOKEN
the token you mint below

Three repository secrets. Nothing else to configure: you set the brand by talking to your Mind. Run onboarding once by hand: Actions, imaji, Run workflow, set job to onboard.

03

Mint a kit token

The only credential imaji issues. It authorises posting a kit and belongs in your repository secrets; your kit pages live at a read id derived from it, so a kit link is safe to share.

Shown once. Kits for it appear at /k/9b67acb83bf6c255a882cd82.

04

It ran, for real

imaji announced imaji. The Mind imaji.labs took the job, was onboarded from this repository’s own README and CSS tokens, then handled two releases through the workflow’s exact path, posting each kit on its own.
